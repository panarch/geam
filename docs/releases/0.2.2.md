# Geam 0.2.2

Geam 0.2.2 adds a managed workflow for calling Gleam from Rust, makes
standalone preparation easier to follow, aligns the public reference packages
with Geam releases, and introduces a validated documentation site.

## Changes

- Embed Gleam in a Rust application with `geam embedding init`, `sync`, and
  `check`. Generated, committed Rust bindings support repeated calls to public
  Gleam functions across scalar, tuple, `Result`, `Option`, and recursive
  `List` values. Plain and provider-backed projects share the same
  `project().compile()` loading shape. Rust applications can select only the
  `embedding` feature to avoid pulling in the CLI, provider macros, and built-in
  integrations.
  ([#136](https://github.com/panarch/geam/pull/136),
  [#148](https://github.com/panarch/geam/pull/148), @panarch)
- Inspect persisted standalone provider selections with
  `geam provider list`. Preparation and execution now report real phases as
  append-only `geam:` lines while preserving native Gleam and Cargo output,
  making first builds, provider discovery, and repeated runs easier to follow.
  ([#134](https://github.com/panarch/geam/pull/134),
  [#142](https://github.com/panarch/geam/pull/142), @panarch)
- Run the text-pattern reference package on either Erlang or Geam through its
  matching Hex package and Rust provider. Release automation publishes those
  artifacts at the Geam release version, keeps the reference and Rust embedding
  manifests aligned during preparation, and verifies the public discovery,
  approval, locking, and execution path before creating the GitHub Release.
  Abandoned release preparations can be cleaned up and run again without
  reusing stale branch state.
  ([#132](https://github.com/panarch/geam/pull/132),
  [#135](https://github.com/panarch/geam/pull/135),
  [#144](https://github.com/panarch/geam/pull/144),
  [#151](https://github.com/panarch/geam/pull/151), @panarch)
- Reorganize the documentation around running Gleam projects, embedding Gleam
  in Rust, and authoring host providers. Add explicit compatibility and runtime
  boundaries, a Zensical site configuration with strict CI builds, and clearer
  positioning of Geam as a Rust runtime and embedding layer rather than a
  source-to-source compiler.
  ([#145](https://github.com/panarch/geam/pull/145),
  [#147](https://github.com/panarch/geam/pull/147),
  [#149](https://github.com/panarch/geam/pull/149), @panarch)
- Make verification independent of warm CI caches and build every workspace
  crate's public Rust documentation as a merge check. The Rustdoc build now
  handles Geam's recursive public planner types without overflowing its default
  recursion limit.
  ([#141](https://github.com/panarch/geam/pull/141),
  [#143](https://github.com/panarch/geam/pull/143), @panarch)

## Compatibility

- Existing standalone projects, provider crates, and default-feature Rust
  consumers require no source migration from Geam 0.2.1. The Rust 1.96,
  Gleam 1.18.1, and 64-bit target requirements are unchanged.
- `geam prepare` and `geam run` now write progress lines and forwarded native
  tool output to stderr. Automation that compares complete stderr output should
  update its expectations.
- The public `example_text_pattern` Hex package and
  `geam-example-text-pattern` Rust provider now follow the Geam release version;
  use version 0.2.2 of both when testing this release.
