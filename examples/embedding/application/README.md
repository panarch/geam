# Rust Embedding Application

This complete example uses Gleam to review incoming inventory in a Rust
application. Gleam normalizes item codes, validates them through the
text-pattern provider, and returns accepted rows and rejection reasons. Rust
passes the returned List back to Gleam for a total and the first valid item,
then prints the review.

## Workflow

For a new Rust application, start with `geam embedding init` in its Cargo
package directory. Write public Gleam functions, run `geam embedding sync`,
then use the generated bindings from handwritten Rust and build with Cargo.
The [embedding guide](../../../docs/embedding.md#make-your-first-call) walks
through the first call. The preceding [external provider example](../provider)
shows provider setup on its own before this application combines it with stdlib
IO and structured data.

This example is already initialized. Its Cargo name
`geam-rust-embedding-application` determines the Gleam package and public module
name, `geam_rust_embedding_application`, under `gleam/`. To change its Gleam
interface, edit that module, run sync, and update the Rust calls;
`src/geam_bindings.rs` is regenerated by sync.

In this repository, checked-in path dependencies and a Cargo patch connect the
application to the local Geam and text-pattern provider sources. In a new
application, init adds Geam, and sync discovers and asks for approval of missing
native providers. Existing compatible declarations are reused.

## Read The Example

1. [main.rs](src/main.rs) loads and seals the generated project, supplies state
   and provider configuration, submits inventory rows, and handles output.
2. [inventory.rs](src/inventory.rs) calls the three generated functions. Its
   application-owned `Review` retains the checked rows and summary, and
   `write_report` handles Rust Result and Option values for presentation.
3. [geam_rust_embedding_application.gleam](gleam/src/geam_rust_embedding_application.gleam) exposes the batch,
   total, and first-valid operations. [inventory_rules.gleam](gleam/src/geam_rust_embedding_application/inventory_rules.gleam)
   implements normalization and provider-backed validation with the opaque
   `Stock` type. `Stock` cannot currently appear in a generated Rust function
   signature, so the root module converts it to a Tuple before returning its
   data to Rust.

`geam_bindings.rs` is generated by `geam embedding sync`. The general
[embedding guide](../../../docs/embedding.md) explains project setup,
synchronization, supported data, and ownership.

The two summary calls borrow the same retained List without copying its rows
back into a Vec. Writing the report explicitly reads every row for display;
it does not change how the List is passed back to Gleam.

## Run

From this directory, with Geam, Rust, and Gleam installed:

```sh
geam embedding check
cargo run --quiet --locked
```

Check restores missing locked Gleam package sources without changing the
application's declarations, lockfiles, or generated Rust. The existing provider
declaration needs no new approval. After editing Gleam, use
`geam embedding sync` before the next Cargo build.

The application prints:

```text
validating inventory
Inventory validation:
  AB-12: 3
  Row 2 rejected: invalid code
  C-7: 4
  Row 4 rejected: quantity must not be negative
Total quantity: 7
First valid item: AB-12 (3)
```

## Verify

```sh
geam embedding check
cargo test --locked
```

The tests beside `inventory::review` exercise the same calls as the application
and check exact values and report text for mixed, all-rejected, and empty
receipts. They also check repeated use of one module, captured IO, and Echo.
[tests/runs.rs](tests/runs.rs) checks the real binary's complete output.

Keep both lockfiles, Gleam source, and generated Rust in source control. Cargo
`target/` and `gleam/build/` remain caches. Runtime compilation reads this nested
source project; the executable does not bundle it.
