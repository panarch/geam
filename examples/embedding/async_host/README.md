# Rust Embedding: Async Host

This example lets a Gleam call await Rust work without giving Geam an async
runtime of its own. The Rust application registers two async host functions and
drives the returned Future with its chosen executor.

The `around` host function reads caller-owned state, invokes a typed Gleam
callback, and updates state after the callback returns. That callback reaches
`pause`, which yields once before completing, so the same call also demonstrates
a real Pending and resume transition.

## Read The Example

1. [geam_rust_embedding_async_host.gleam](gleam/src/geam_rust_embedding_async_host.gleam)
   keeps the public `calculate` function and its callback in Gleam.
2. [host.rs](src/host.rs) defines the embedding-owned async registrations and
   the caller-owned run state.
3. [main.rs](src/main.rs) adds those hosts to the generated project, binds the
   async handles, seals one resumable module, and awaits its call with the
   `futures` executor.
4. `geam_bindings.rs` is generated by `geam embedding sync`.

The fallback bodies on the two external functions keep the Gleam project
independently checkable. `with_async_hosts` selects the Rust implementations for
this embedding application.

## Run

With Geam, Rust, and Gleam installed, run from the repository root:

```sh
cd examples/embedding/async_host
geam embedding check
cargo test --locked
cargo run --quiet --locked
```

The application prints:

```text
value: 46
completed: 1
input: 20
after host: 45
```

Geam exposes an ordinary Rust Future. An async application can await the same
call directly from its existing executor instead of using `block_on`.
